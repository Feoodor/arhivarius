# Архивариус

![logo](logo.png)

**Офлайн-ассистент разбора архива папок на локальной LLM.** Читает *содержимое* файлов
(документы, PDF, таблицы, картинки — через зрение модели), предлагает имя по вашему регламенту
и место в вашей структуре папок, а переносит только то, что утвердил человек.
Никаких облаков и API-ключей: файл, карта и решения остаются на вашем компьютере.

English: [README.en.md](README.en.md) · [Скачать .exe](https://github.com/Feoodor/arhivarius/releases/latest)

## Для чего

Папки годами обрастают свалками: «Разобрать», «Новая папка (2)», `IMG_2041.jpg`,
документы не там и не так названные. Разбирать это руками — недели. Архивариус делает
черновую работу: модель читает каждый файл и предлагает, как его назвать и куда положить;
человек только утверждает. Всё остальное — страховки: журнал операций, откат пачкой
одной кнопкой, ни одного удаления.

## Возможности

| | |
|---|---|
| 🧠 **Двухпроходный анализ** | проход 1 выбирает раздел по полной карте папок, проход 2 — точную папку внутри его поддерева. Видит любую глубину вложенности |
| ⚡ **Правила раньше модели** | однозначные случаи (имя уже по регламенту, имя файла называет существующую папку, повторный хеш, ярлык) решаются детерминированно без запроса к LLM |
| 📖 **Few-shot прецеденты** | утверждённые вами решения подмешиваются модели как примеры — система учится на ваших подтверждениях без дообучения |
| 👁 **Зрение** | картинки и PDF-сканы читаются визуально (gemma3): тип, тема, дата и даже текст, написанный на афише |
| 🗣 **Извлечение и OCR** | docx/pdf/xlsx/pptx/rtf, метаданные фото и аудио, распознавание через tesseract |
| 🧭 **Навигатор папок** | отдельный проход: куда перенести целую «папку разбора», со статистикой (текст/картинки отдельно) и прогнозом времени |
| 📂 **Окно «Папки»** | пустые папки → корзина Windows (с меткой «не трогать»), слияние одноимённых двойников в канон, подсказки недостающих папок |
| 🖼 **Похожие фото** | перцептуальный хеш (dhash) находит пересжатые и переименованные копии одного кадра |
| 🔎 **Эмбеддинги (опция)** | смысловой поиск папок-кандидатов локальной embedding-моделью (bge-m3) |
| 🛡 **Страховки** | дата в имени обязана быть подтверждена текстом/EXIF; выдуманная папка режет уверенность; цель вне выбранного раздела → проверка; конфликт имён → `_v2` + проверка |
| 🗂 **Карта предложений** | Excel-совместимый CSV (`;` + BOM), фильтры, просмотрщик «было/станет» с содержимым файла рядом |
| ↩️ **Журнал и откат** | каждая пачка переносов откатывается одной кнопкой; файлы не удаляются никогда |
| 🌍 **10 языков интерфейса** | Русский, English, Беларуская, Українська, Polski, Deutsch, Español, Français, Italiano, Português, 中文 |
| 🔌 **Сеть** | считать модель может Ollama с другого компьютера в локальной сети |

## Быстрый старт

1. Установите [Ollama](https://ollama.com) и модель:
   `ollama pull gemma3:12b` (для смыслового поиска по желанию — `ollama pull bge-m3`).
2. Скачайте `Arhivarius-*.exe` из [последнего релиза](https://github.com/Feoodor/arhivarius/releases)
   и запустите. Python не нужен.
3. Первый запуск создаст `config.json` и редактируемые промпты (`prompt.md` — регламент
   названий и правила раскладки; `prompt_user.md`, `prompt_section.md`, `prompt_folder.md`).
   Настройте корень папок и пороги уверенности в «⚙️ Настройки».
4. Рабочий цикл: «🔄 Обновить» (снимок) → «▶ Начать анализ» (партия 5–20 файлов) →
   «👁 Смотреть и утвердить» → «🧪 Пробный перенос» → «✅ Утвердить помеченные».

## Безопасность данных

- Программа работает **полностью локально**: содержимое файлов уходит только в вашу
  Ollama на вашем (или указанном вами сетевом) компьютере. В облако не отправляется ничего.
- Файлы **не удаляются и не перезаписываются**: «корзина» — это перенос в отдельную
  папку, пустые папки уходят в корзину Windows; всё с журналом и откатом.
- Ярлыки: для писем о событиях программа может создать настоящий `.lnk` в папке
  Входящие/Исходящие. В Google Drive такие ссылки не работают между компьютерами —
  облачную ссылку при необходимости создайте средствами диска (программа её сама не
  заменяет); нулевые файлы-ссылки Google Docs (`.gdoc`, `.gsheet`…) в мусор не попадают.

## Сборка из исходников

```
pip install -r requirements.txt      # PyMuPDF, openpyxl, Pillow (опциональные читалки)
python app.py                        # интерфейс
python selftest.py                   # 100+ автотестов на временной папке
python etalon_check.py               # точность на эталонных файлах (нужна Ollama)
pyinstaller Архивариус.spec          # один .exe
```

## Идеи и доработки

Проект растёт из идей пользователей — создайте [Issue](https://github.com/Feoodor/arhivarius/issues)
или тему в [Discussions](https://github.com/Feoodor/arhivarius/discussions): новый формат
файлов, язык интерфейса, правило именования, поведение модели. Баги — особенно с логом —
отдельная благодарность. PR приветствуются.

Дорожная карта: пакетный режим по расписанию, сравнение «до/после» для спорных папок,
экспорт статистики, выбор embedding-модели.
