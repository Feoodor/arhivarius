 ЧАСТЬ 1. ПОДГОТОВКА ДИСКА
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

1. СОБЕРИ ВСЁ В ОДНОМ МЕСТЕ
   Файлы отдела лежат вразброс: рабочий стол, «Загрузки», Telegram, распакованные
   архивы, флешки. Соберите их на диск отдела, каждая группа — в свою подпапку
   («Разобрать-2026-05», «Фото со слётов»). Не сваливайте в одну кучу: по названию
   папки проще проверять результат.

2. ДУБЛИКАТЫ  — кнопка «Дубликаты»
   Поиск по содержимому, а не по имени. Помечать, не удалять: «копия» в отделе
   нередко означает подписанный экземпляр или версию с правками.

3. СТАРЫЕ ФОРМАТЫ  — «Старые форматы: список» → «конвертировать»
   .doc, .rtf, .odt модель не читает. Конвертация создаёт рядом .docx, оригинал
   не трогает. Кнопка «Оригиналы после конвертации» найдёт, у чего уже есть .docx:
   список ляжет в «Корзину», а старое вы перенесёте туда по своему решению.

4. БИТЫЕ ФАЙЛЫ  — «Битые файлы»
   Пустые, обрезанные, с чужим расширением. Пишет broken_files.csv. Такие
   материалы решает человек, а не модель.

5. НЕЯСНОЕ — во временную папку разбора (00_Разобрать)
   Одной-двумя папками, БЕЗ самодельной структуры внутри: она сбивает с толку и
   модель, и людей. Ветвь «Разобрать» поэтому скрыта из промпта.

 ЧАСТЬ 2. РАЗБОР ПРОГРАММОЙ
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

6. СНИМОК → ПАРТИЯ
   «Обзор» → снимок диска (только чтение) → партия 5–20 файлов. Модель читает
   содержимое, а не имя файла, и предлагает имя по регламенту + папку из
   существующей структуры. Режимы: 🧹 разбор завалов · 🧭 ревизия структуры ·
   🔍 проверка системы · 🪜 сначала система, потом разбор.
   Двухпроходный разбор (Настройки → 🗺 Карта папок): в первом запросе модель
   выбирает только РАЗДЕЛ по скелету карты, во втором — точную папку внутри его
   полного поддерева. Так видны даже очень глубокие ветки; цена — примерно
   вдвое больше запросов на файл. Если второй проход уходит из выбранного
   раздела, строка обязательно встаёт на вашу проверку.

7. «📦 ПАПКА ЦЕЛИКОМ» — новый режим для неясных папок
   Модель видит ВСЕ имена файлов папки одним запросом: серии, пары «афиша+фото» и
   безымянные снимки получают согласованные имена. Картинки могут пройти через
   зрение (кнопка спросит). Все предложения падают в карту со статусом «проверка».

8. ПРОВЕРКА КАРТЫ — ваш ручной контроль
   Двойной щелчок по строке → просмотр: слева содержимое (можно выделять и
   копировать), справа решение. «Было» показывает старый путь целиком, «Станет» —
   новое имя (переключатель «показ»: имя / имя+путь / путь). Папку для переноса
   можно выбрать кнопкой 📁 прямо в проводнике. Кнопка «🔬 Перепроверить глубже»
   отдаёт файл модели повторно и думает в ТРИ ШАГА: сначала выписывает факты из
   содержимого, потом собирает имя, потом подбирает папку по карте и соседям — с полным
   текстом и вашим комментарием. Улучшенный вариант показан отдельной карточкой рядом с
   первым; берите его кнопкой «✔ Взять этот вариант» или правьте руками.

9. 🔁 ПЕРАРАЗБОР БЕЗ НОВОГО СКАНА
   Отказались от предложения — не нужно сканировать диск заново: выделите строки
   (или ничего — тогда уйдут все «отказы»), нажмите «Переразобрать выбранное».
   Строки уберутся из карты, и следующая партия предложит им новые имя и папку.
   Полезно и для старых файлов: отмечайте нужные и запускайте переразбор, когда
   промпт стал умнее.

10. 🩺 ПРОВЕРИТЬ СТРАННОЕ + 🧠 УРОКИ
    «🩺 Проверить странное» просматривает ВЕСЬ список по понятным признакам и помечает
    подозрительное: мусорное имя (IMG_2041, «копия», uuid), файл, завалявшийся в развале
    без разбора, цель, которой нет на карте, уверенное расхождение года имени и папки,
    два файла на одно имя, «отмечено, но пусто». Сначала — сводка с примерами, затем
    помеченные строки мягко перепроверяются моделью в те же три шага. Ничего само не
    переносится. Второстепенная «🧠 Уроки» собирает ваши правки и комментарии в
    правила-черновики learned_rules.md; в промпт попадают только строки, подтверждённые
    вами знаком «✓».

11. ПРОБНЫЙ ПЕРЕНОС → ПРИМЕНИТЬ
    Dry-run ничего не меняет. «Применить» спрашивает слово APPLY, ведёт журнал
    операций и файл отката. Перенесённое уходит в историю и больше не предлагается.

12. КОРЗИНА — как безопасно расстаться с мусором
    Программа файлы не стирает. «Корзина» собирает кандидатов: пустые, битые,
    лишние копии, оригиналы после конвертации. Подтверждение словом УБРАТЬ —
    ПЕРЕМЕЩЕНИЕ в «99_Корзина на проверку». Там смотрите ещё раз и удаляйте сами.

 ЧАСТЬ 3. ВОПРОСЫ И ОТВЕТЫ
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

• «Что за план папок?» — на странице «Структура» кнопка «📄 План папок» пишет
  structure_plan.txt: список папок каркаса (разделы регламента, годы). Он
  редактируемый: уберите лишнее, добавьте своё. «Создать папки из плана» — только
  mkdir по этому списку: пустые папки, без переносов и удалений. Нужен, чтобы
  модели было куда класть файлы, когда структура ещё не развернута.

• «Где увидеть вывод „Имена: предложения“?» — это dry-run переименований: список
  пишется в output-папку (имена_починки*.csv / журнал), а «применить» выполняет.
  Результат виден в Журнале и в CSV, которые открываются кнопками внизу «Журнала».

• «Можно ли .exe?» — да: PyInstaller собирает Архивариус.exe одним файлом. Но
  это снимает только зависимость от Python. Ollama и модель (≈8 ГБ) получателю
  всё равно придётся поставить — модель весит гигабайты и в exe не помещается.
  Поэтому для передачи: архив папки программы + README (установка Python или exe,
  установка Ollama, ollama pull). Если у получателя нет своей видеокарты —
  программа умеет обращаться к Ollama по сети: укажите её адрес в «Настройках».

• «Я поделился — буквой диска всё сломается?» — нет. Корень отдела хранится
  списком вариантов (Настройки → 📁 Пути), при запуске берётся первый
  существующий; пути результатов подтягиваются следом.

• Горячие клавиши: Ctrl+C / V / X — копировать-вставить-вырезать везде,
  Ctrl+A — выделить всё, в просмотре Ctrl+S — сохранить, Esc — закрыть.

ГЛАВНОЕ: программа не удаляет файлы. Она перемещает и переименоывает утверждённое
вами, а лишнее убирает в отдельную папку — на ваше решение.
